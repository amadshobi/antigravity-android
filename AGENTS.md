# AGENTS.md

Antigravity for Android (AGY v2): a **Gradle-free** Android host app (`com.agy`) that runs an AI coding environment directly in Bionic userspace and serves a local web UI inside a WebView. The build system is bash + Python; there is no Gradle, npm, or pyproject to fall back on.

## Layout
- `app/src/main/java/com/agy/` — Android host: `ui/MainActivity`, `bridge/` (JS bridge), `ui/webview/` (WebView, CSP injection), `runtime/`. Java package stays `com.agy` even in the dev APK.
- `modules/{core,patches,io,env,builder,runner}/` — independent subsystems, each with its own `README.md`; all but `runner` expose `tests/run_all.sh` (`runner` ships `test_e2e.sh`).
- `web/` — web UI sources plus committed build output under `web/generated/**`.
- `config/app.env` — single source of truth for package names, ports, versions (plain `KEY=VALUE`, parsed by `01_gen_config.py`; no shell logic).
- `config/AGENTS.md` — device-side rules auto-loaded inside the app; project rules are summarized below.
- `tools/` — committed `android.jar`, `r8.jar`, `debug.keystore`; jar hashes are pinned in `config/paths.env`. Never replace them.
- `modules/core/pristine/language_server.tar.gz` (~52 MB) is committed and required by asset staging — don't delete it.

## Commands
APK build (host needs `python3`, a JDK with `javac` (CI pins 17), `aapt`, `apksigner`):
- `bash build.sh` → `dist/antigravity.apk`
- `bash build.sh --region-bypass` → `dist/antigravity-region-bypass.apk`
- `bash build.sh --dev --region-bypass` → `dist/antigravity-dev-region-bypass.apk` (`--dev` alone → `antigravity-dev.apk`)
- Other flags: `--prefix <name>`, `--out <path>`. `--fast` is currently a no-op: it is parsed and prints a banner, but no phase reads `FAST_BUILD` (the builder README claims otherwise).

Tests (`bash` + `python3`):
- `bash test_all_modules.sh` — 6 suites. Suite 6 (`modules/runner/test_e2e.sh`) is a live on-device run: it prepares/starts the core on port 45159 and needs `/data/user/0/<pkg>`. On a desktop it fails; run suites individually instead.
- Per module: `bash modules/<module>/tests/run_all.sh`
- Single test: `python3 modules/io/tests/test_plugin_router.py`

Web layer:
- `bash web/build.sh` — regenerates `web/generated/**` from `src.manifest`, patches `generated/main.js`, then `node --check` every bundle.
- `bash web/tests/selftest.sh` — builds in a temp copy, proves upstream `main.js` is untouched, rejects nested IIFEs, and runs `test_extension_host.sh` (static checks + `node` smoke test).
- Single: `bash web/tests/test_extension_host.sh`

## Build facts that bite
- Every build wipes its own `build/` subdirectories (not `dist/`). `05_stage_assets.py` runs `prepare_runtime` and `web/build.sh` itself, so a stale `web/generated` won't ship — but commit regenerated bundles when you change `web/src/**`.
- All editions are signed with `tools/debug.keystore` (alias `androiddebugkey`, pass `android`); in-place upgrades depend on that exact keystore. CI only generates it when missing.
- `targetSdk 28` is deliberate: Android 10+ W^X only permits exec from app data at API ≤ 28, and the core/glibc binaries are exec'd directly. Don't bump it.
- `01_gen_config.py` rewrites `versionName`/`versionCode` in the build manifest from `config/app.env`; the values in the committed `AndroidManifest.xml` are only defaults.
- Dev edition = `com.agy.dev`, port 45158, `debuggable=true`; sources and `R` remain in `com.agy` (a fallback `com.agy.R` is generated by `02_r_java.sh`).
- Phases live in `modules/builder/` (`01_gen_config.py` … `09_verify.sh`, plus `align.py`), orchestrated by `build_apk.sh`. Change behavior there, not in the root `build.sh` (it only forwards flags).

## Web layer
- Add/edit fragments under `web/src/**`, then regenerate. Never hand-edit `web/generated/**` or `web/main.js` (upstream bundle).
- `web/src.manifest` grammar: `bundle [iife] <out>` opens a bundle, following `src/<path>` lines are concatenated in order, and any other line fails the build.
- `web/patch_main.py` injects the Desktop Mode switch and Eza logo into `generated/main.js`; it is idempotent and fails the build if its regex no longer matches.
- `index.html` script order is load-bearing: boot fragments → `bridge.core.js` → `extensions/extension_host.js` → `generated/main.js`.
- `window.AGY` is the extension API (`plugins.register`, `ui.*`, `events.*`). There is no auto-discovery for web plugins: a plugin source must call `AGY.plugins.loadScript` itself.
- CSP is injected by Java `AppHtmlInjector`: `style-src 'unsafe-inline'` is allowed, `script-src` does not include `https:` — remote scripts won't load.

## I/O bus & runtime plugins
- `EventBroker` dispatches to in-memory handlers (`register_handler` / `unregister_handler`) and to scripts in `modules/io/outputs/` routed by `spec/default_routes.json` (JSON envelope on stdin).
- Runtime plugins are off by default: `AGY_ENABLE_PLUGINS=1` enables `~/.gemini/config/plugins` and `~/.gemini/plugins`; `AGY_PLUGINS_ALLOW_WORKSPACE=1` additionally allows `<cwd>/.agents/plugins`. `attach_plugins(broker)` is called by `fifo_input.py`, `unix_socket_input.py`, and `stream_splitter.py`.
- Plugin runtime scripts must resolve inside their own plugin directory; on timeout the child is killed, and non-zero exit plus stderr tail is logged.

## CI & release
- Only workflow: `.github/workflows/build-and-release.yml`. Runs on tag `v*`, push to `dev`, or manual dispatch; builds all three APKs plus `SHA256SUMS.txt` and uploads artifact `antigravity-binaries`.
- The publish step is gated on `refs/tags/v`; a manual `workflow_dispatch` never publishes a release even though it asks for `tag_name`. Dispatching with `--ref <tag>` *does* publish, because `github.ref` is the tag.
- Observed once: pushing tag `v2.4.2` created no run at all. After tagging, check `gh run list`; if no run exists, use `gh workflow run build-and-release.yml --ref <tag>` to build and publish from that tag.
- Release = bump `APP_VERSION_NAME`/`APP_VERSION_CODE` in `config/app.env` (+ `RELEASE_NOTES.md`), commit, then push tag `v<APP_VERSION_NAME>`.
- Commit messages follow Conventional Commits (`feat:`, `fix(ci):`, `chore(release):`).

## Project rules worth keeping
- From `config/AGENTS.md`: keep each module `README.md` in sync with code/interface/flag changes, avoid hardcoded paths where `$PREFIX`/`$HOME`/`$PROJECT_ROOT` work, avoid dead or duplicated state, never commit temporary build artifacts.
- Ports `45157` (release) and `45158` (dev) are reserved for the core webview/API; never bind dev servers there.
- On device: no `bwrap`; `/storage/emulated/0` is `noexec` (invoke via `bash`/`python`/`sh`); quote paths; use `GIT_CONFIG_NOSYSTEM=1` and `safe.directory` for git on shared storage.

## Windows dev hosts (this workspace)
- `core.autocrlf=true`, so `.sh` files check out CRLF and `bash` (WSL) dies on `set -euo pipefail` ("invalid option name"). Convert scripts to LF in place before running; git reports no content diff afterwards.
- `bash` resolves to WSL here; Python subprocesses pass Windows paths, so `modules/builder` and `modules/runner` suites fail (exit 127, no `aapt`). Verify APK/builder changes on Linux (CI) or an Android device.
